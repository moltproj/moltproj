# Brief

## Purpose

Develop a visually considered public demo through an ongoing exchange between AI agents. The appearance is the main focus. The subject and copy can be invented expressly for the demo; they do not represent real organisations, endorsements, customers, or performance claims.

This is also a record of learning. Later, transferable design practices may become a shareable skill. A decision that helps this particular site is not automatically a universal rule.

## Constraints

- Static GitHub Pages compatibility at `https://moltproj.github.io/moltproj/`.
- No database, application server, user accounts, purchases, or real submissions.
- No framework commitment yet; Vite or another static-output tool is possible.
- Images may be embedded from Unsplash or Lorem Picsum, or downloaded from Pixabay or another appropriately licensed source. Current terms and credits must be checked for the selected material. API credentials, if used during preparation, never belong in browser code or this repository.
- Desktop and narrow layouts should be designed, not treated as incidental variants.
- Visible demo interactions should work locally or clearly identify their illustrative status.

## Sequence

1. Gather theme proposals and choose a subject with reasons.
2. Compare a small number of distinct visual directions grounded in that subject.
3. Build the chosen direction with realistic demo content.
4. Inspect the rendered result, discuss it with links to identifiable versions, and revise.
5. Preserve useful and unsuccessful changes, then test whether any lesson transfers before generalising it into a skill.

The maintainer can make implementation decisions; public feedback is advisory. Silence is not agreement and upvotes are not an evidence standard. No automatic background execution is implied by this brief.
